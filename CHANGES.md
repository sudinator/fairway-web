# 177.60.260819 — Version ledger guard + CI psql hardening

**Commit summary:** `177.60 Version ledger guard and CI psql hardening`
**Base:** staging @ commit `1de2898` (the 177.59 code drop, already deployed)
**Risk:** very low. No application code. No migrations. No schema, RLS or RPC changes.

## Why this is 177.60 and not a re-cut of 177.59

177.59 is already committed and deployed to the staging app. Relabelling that drop would rewrite a
version that has shipped. The correction ships forward as 177.60, and 177.60 also adds the
DEPLOY_NOTES entry 177.59 should have had.

## What went wrong

177.59 went to staging with `package.json` still reading `177.58.260816`, so the Help screen kept
reporting the previous version. Nothing caught it — typecheck, lint, 55 guards, tests and the build
were all green, because a version string is data, not code.

The version bump had been left as a manual step with no gate behind it. That was a process error on
my side: a mandatory release step should not depend on being remembered.

### `ci/check_version_ledger.py` — NEW
Fails the build when `package.json` FEATURE.EDIT does not match the newest DEPLOY_NOTES heading,
and when entries are prepended out of order.

The DATE segment is deliberately not compared. DEPLOY_NOTES records the day the notes were written;
`scripts/write-version.mjs` stamps the US/Eastern date the build actually ran. A release prepared
late or deployed the next morning would legitimately differ, and a guard that fires on legitimate
cases gets switched off.

Negative-tested: reverting package.json to 177.58 fails with the exact message describing this
incident; restoring it passes.

### `.github/workflows/ci.yml` and `.github/workflows/robustness.yml`
The psql install step now checks whether `psql` is present before calling apt. Both files had the
identical step. The fallback branch is byte-identical to the previous command, so the worst case is
unchanged behaviour. Both files re-validated as parseable YAML with unchanged job structure
(`verify`; `schema-guard`, `onepager-sync`).

Context: on 2026-08-19 this step stalled 8m41s in `ci.yml` on an unreachable
`azure.archive.ubuntu.com` mirror, while `robustness.yml` completed the identical step in a 4m21s
run on a different runner. Transient infrastructure, not code — a plain re-run went green. The fix
is preventive.

## Contracts and intentional behavior

New outputs are local diagnostic events and a manual JSON export. Data collection is allowlisted and bounded (150 events and 48 KiB text per session; four sessions; seven days). Timeline entries carry timestamp/sequence/session/app version. HTTP observation preserves the exact input/init/signal, original Response and original rejection; it never reads/clones bodies or retries a request. Only x-vercel-id/sb-request-id correlation response headers are read. No authentication header, cookie, query string, user name or score value is stored. Runtime errors record error class, allowed code and same-origin chunk/line/column, not raw messages/stacks. Request paths normalize dynamic app identifiers. Report headings include app/backend origins, build and browser/time/viewport/notification-permission metadata, controlling-worker version/registration state and cache-version names. Backup-key counts are not evidence of pending work. Cookie expiry and hidden cross-origin redirect targets remain inaccessible.

The recorder is attached once with reference-counted cleanup, including StrictMode/re-entry. Network/lifecycle observers do not navigate, prevent errors, mutate authentication or activate a worker. Realtime state is sampled by read-only connection/channel-count calls; channel names/payloads are excluded. The worker status query replies with its version only; worker install/cache/asset failures send best-effort fixed metadata to existing app clients without changing worker outcomes. Local-storage writes are throttled, flushed on page hide/update navigation/export and bounded to diagnostic keys. Quota/unavailable storage falls back to memory; no score eviction or diagnostic upload. Current-account history is selected on export, direct account switches isolate memory, and existing sign-out cleanup additionally clears diagnostic memory/history. Legacy raw opt-in traces remain outside the new export.

Changed save helpers retain every original argument (save/onState/same/isStored and per-row backup/watermark/confirm/lock/pause/revision/send/clock), return, callback order, queue/acknowledgement rule, database payload and side effect. Record calls observe selected existing transitions. Existing local draft writes remain synchronous; retry/tidy/error behavior remains, with additional metadata-only local-success/failure events. Sign-in retains its existing returned/throwing behavior. Update checks/activation/restart policy and the 212.99 redirect/cache admission rules remain; only metadata and read-only worker status are added.

## Contracts and intentional changes

Inputs: existing version response, worker registration/controller/state, update target from URL/session, storage availability, diagnostic events, device role; new optional user description, open/close and manual refresh. Outputs: readable summary, retained update-result metadata, manual JSON userDescription/updateStatus fields, refresh check. Worker query remains read-only and bounded; no activation, navigation, score read/write or cache mutation. The summary has explicit untested/unavailable/no-reply/mismatch states. Asynchronous responses are fenced after unmount and superseded refreshes.

Update request/response arguments, credentials, manual redirect handling, cancellation/timeouts, activation message, navigation URL, pending-banner/no-dismiss policy, eight-second success expiry and all scoring/draft contracts remain. Intentional changes: fixed metadata for last outcome survives the transient banner and reload in the same tab; check/download/activation/restart failure phase is exposed, with existing retry action. Result data is validated, reconstructed from fixed fields and bounded (sessionStorage <=1,000-character read; seven-day TTL). Broken storage leaves in-memory feedback. No old success is replayed as a new pending update. The loaded version, not navigation alone, confirms restart success.

Description is controlled React text, max 500 characters; trim/control-character normalization on export, whitespace-only omitted. It is passed directly to manual JSON, never event history or local/session storage. Text remains editable after cancel/failure; new panel/reload starts blank. Automatic metadata continues to exclude bodies/headers/credentials/names/scores, but the optional user-provided context includes what the user types and the UI warns about sensitive data. Existing share-sheet/cancel/download/failure/retry outputs remain.
